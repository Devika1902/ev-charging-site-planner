# Allego Germany · Network Planning Prototype

A web app for exploring hypothetical EV fast-charging candidate locations in Germany. It includes a ranking dashboard, map view, adjustable scoring priorities, candidate drill-downs, CSV import/export, a printable report and a Python data-generation, validation and model-training pipeline.

> **Data notice:** Every built-in candidate and indicator is synthetic and exists to demonstrate the workflow. It is not official market evidence, an investment recommendation, a statement of Allego plans, or evidence of land rights. The map is a simplified schematic with approximate city-area markers; it is not a geographic boundary or parcel map.

## Run the dashboard

Serve the folder locally so the dashboard can load the candidate CSV and trained scores:

```powershell
python -m http.server 8000
```

Then open `http://localhost:8000`. The app has no build step or JavaScript dependencies. Google Fonts are optional; local system fonts are used when offline.

## Use the dashboard

- **Overview:** filter regions, choose the transparent weighted score or trained model, adjust score weights, inspect the map and open candidate detail cards.
- **Opportunity map:** explore candidate markers, labels and opportunity shading.
- **Candidate sites:** search, compare, and export ranked rows as CSV.
- **Data & methodology:** review the score formula, data-source considerations, limitations, and upload a candidate CSV.
- **Export report:** opens a printable HTML management shortlist (use the browser print dialog to save as PDF).

Weights are normalized to 100% automatically. The screening score is:

`demand × w₁ + traffic × w₂ + EV adoption × w₃ + supply gap × w₄`

All component indicators are on 0–100 scales. `nearby_supply` represents relative existing charging coverage, so `supply_gap = 100 - nearby_supply`. Demand is an input indicator; the demo does not claim an empirically calibrated demand model. A high traffic score alone does not establish charging demand or stopping behavior.

## Candidate CSV format

Download the template from **Data & methodology**. Required headers:

`location, region, demand, traffic, ev_adoption, nearby_supply, access, confidence, lat, lon`

Optional headers: `opportunity, validation_note`. Indicator fields must be numeric 0–100; coordinates must be decimal degrees. Confidence accepts High, Medium or Low. Upload replaces the current in-memory candidate set; reloading the page restores the 22,000 generated planning cells and the model output when present.

## Run the analysis pipeline

Python 3.10+ is required. Install the packages for model training and the Excel decision matrix:

```powershell
python -m pip install -r requirements.txt
python pipeline/generate_demo_data.py --rows 22000 --output data/candidates.csv
python pipeline/train_model.py data/candidates.csv --output-dir outputs/model
python pipeline/analyze.py data/candidates.csv --output-dir outputs/analysis
```

Optional weight arguments are `--demand`, `--traffic`, `--ev-adoption`, and `--supply-gap`; defaults are 35, 25, 25 and 15. Outputs include:

- `candidate_ranking.csv` · ranked decision matrix
- `candidate_locations.geojson` · point features for GIS exploration
- `data_quality_report.md` · validation findings and limitations
- `decision_matrix.xlsx` · formatted spreadsheet (requires `openpyxl`)
- `outputs/model/opportunity_model.joblib` · trained Extra Trees regressor
- `outputs/model/scored_candidates.csv` · 22,000 candidate rows with trained predictions, loaded by the dashboard
- `outputs/model/training_report.md` and `training_metrics.json` · reproducibility details and holdout metrics

The model uses a fixed 80/20 train/holdout split and seed 42. Its teaching target is a simulated suitability label generated by the demo-data script. Holdout metrics only describe recovery of that synthetic label; they are not real-world performance evidence. The interactive weighted score remains available as a transparent alternative.

## Data plan and limitations

The intended source investigation includes KBA regional BEV and PHEV registrations, Open Charge Map station records, Eurostat GISCO population grids, OpenStreetMap roads, and German traffic counts. This prototype does not connect to these services. Open Charge Map is useful for exploratory competitor mapping, but should not be treated as a complete authoritative inventory; coverage, record quality, licensing and attribution can vary. Confirm record-level terms and attribution before using its data. Separate BEVs from PHEVs in demand assumptions, validate station power and status, and investigate traffic stopping behavior, grid connection, land access and permitting before commercial decisions.
